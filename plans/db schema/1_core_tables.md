# Core Tables & Player Identity

This module defines the foundational entities of Holy War Online: network allocation, faction metadata, and player profiles.

## Related Helper Functions (RPCs)

| Function | Parameters | Returns | Description |
|----------|------------|---------|-------------|
| `allocate_network_address(p_entity_type)` | `TEXT` | inet | Allocates a random unique IP from `network_addresses`. Loops on collision. SECURITY DEFINER. |
| `create_player_on_signup()` | — | TRIGGER | Auto-creates player row on auth.users INSERT (IP auto-assigned via DEFAULT) |
| `update_player_username(p_new_username)` | `TEXT` | JSON | Validates and updates username. Returns `{success: bool, error?: string, username?: string}` |
| `choose_player_sect(p_sect_id)` | `TEXT` | JSON | Sets player's faction. Returns `{success: bool, error?: string, sect_id?: string}` |
| `complete_player_onboarding()` | — | JSON | Marks onboarding complete (requires username + sect). Returns `{success: bool, error?: string, onboarding_complete?: bool}` |
| `get_player_status()` | — | JSON | Returns player profile including `ip_address`, `sect_name`, `sect_emoji`, and onboarding state |
| `get_available_sects()` | — | JSONB | Returns all sects including `ip_address`, ordered by `display_order` |

---

## `network_addresses`

Master registry of all IP addresses across the game. Prevents cross-entity collisions by centralizing allocation. Every player, sect, and virtual machine receives a unique IP from this ledger.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `ip_address` | inet | PRIMARY KEY | Unique network identifier |
| `entity_type` | TEXT | NOT NULL | Owning entity table (`players`, `sects`, `virtual_machines`, etc.) |
| `encryption_level` | INT | NOT NULL DEFAULT 3 | Encryption strength. Hard-locked at 100 for players, 1000 for sects. VMs base at 100 + security chip bonus. |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |

**Indexes:**
- `idx_network_addresses_type` on `entity_type`

**RLS Policies:**
- SELECT: Public read-only (`USING (true)`)
- ALL: Service role only (`auth.jwt()->>'role' = 'service_role'`)

**Triggers:**
- `enforce_encryption_level_trigger`: Forces `encryption_level = 100` for players and `1000` for sects on INSERT/UPDATE (hard-locked).

## `sects`

Faction metadata that drives AI generation and game mechanics. This table is **read-only for players** and populated by seed data.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | TEXT | PRIMARY KEY | Slug identifier: `gilded_path`, `holy_way`, `final_watch`, `black_tribunal` |
| `name` | TEXT | UNIQUE NOT NULL | Display name of the faction |
| `ip_address` | inet | UNIQUE, FK → network_addresses(ip_address) ON DELETE SET NULL | Faction's network identity (hard-locked at encryption_level 1000) |
| `emoji` | TEXT | NOT NULL | Visual icon for the faction |
| `description` | TEXT | | Lore description of the faction |
| `principles` | TEXT[] | NOT NULL DEFAULT '{}' | Array of faction principles used for AI prompts |
| `tone_description` | TEXT | | Tone descriptor for AI generation (e.g., "opulent and grand") |
| `display_order` | INT | GENERATED BY DEFAULT AS IDENTITY | Sort order for UI display |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |
| `updated_at` | TIMESTAMPTZ | DEFAULT now() | |

**RLS Policies:**
- SELECT: Public read-only (`USING (true)`)
- ALL: Service role only

## `players`

Core player data linked to `auth.users`. Tracks username, network location, sect affiliation, and onboarding state.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, FK → auth.users(id) ON DELETE CASCADE | References Supabase auth user |
| `username` | TEXT | UNIQUE | Player name (3-16 chars, alphanumeric + underscore) |
| `ip_address` | inet | UNIQUE NOT NULL DEFAULT allocate_network_address('players') | The unique network identifier used for in-game routing and attacks (hard-locked at encryption_level 100) |
| `sect_id` | TEXT | FK → sects(id) ON DELETE SET NULL | Current faction affiliation |
| `onboarding_complete` | BOOLEAN | DEFAULT false | TRUE when player has completed name + sect selection |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |
| `updated_at` | TIMESTAMPTZ | DEFAULT now() | |

**Constraints:**
- `players_username_check`: `username IS NULL OR (length 3-16 AND ^[a-zA-Z0-9_]+$)`

**Indexes:**
- `idx_players_username` on `username` WHERE `username IS NOT NULL`
- `idx_players_sect_id` on `sect_id`
- `idx_players_onboarding` on `onboarding_complete` WHERE `onboarding_complete = false`

**RLS Policies:**
- SELECT: Authenticated users can read all players
- INSERT: Users can only insert their own row (`auth.uid() = id`)
- UPDATE: Users can only modify their own row (`auth.uid() = id`)
